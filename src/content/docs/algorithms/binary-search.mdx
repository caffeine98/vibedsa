## What it is

Binary search finds a value in a **sorted** array. Each step checks the middle item and throws away the half that can't hold the target.

Checking every item one by one (linear search) takes up to `n` steps. Binary search takes about `log₂ n`. For a million items, that is 20 steps instead of a million.

## How it works

Keep two pointers, `lo` and `hi`, around the part of the array that might hold the target. Then repeat:

1. Look at the middle item, `mid`.
2. If it equals the target, you're done.
3. If it is smaller, the target must be to the right. Move `lo` past `mid`.
4. If it is bigger, the target must be to the left. Move `hi` before `mid`.

### Variant: the first match

With duplicates, plain binary search returns *a* match, not the *first* one. **Lower bound** fixes this. It returns the first index whose value is `>= target`.

It never stops early. When it finds a match, it keeps searching to the left. This also tells you where to insert a missing value.

## Pseudocode

```text title="Pseudocode"
BINARY-SEARCH(A, target):
    lo = 0
    hi = A.length - 1
    while lo <= hi:
        mid = floor((lo + hi) / 2)
        if A[mid] == target:
            return mid
        else if A[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1

LOWER-BOUND(A, target):
    lo = 0
    hi = A.length          // one past the end
    while lo < hi:
        mid = floor((lo + hi) / 2)
        if A[mid] < target:
            lo = mid + 1
        else:
            hi = mid           // mid might be the answer
    return lo
```

## Complexity

| Case | Cost | Why |
| --- | --- | --- |
| Best time | O(1) | The first `mid` is the target. |
| Worst time | O(log n) | Each step halves the range. |
| Space | O(1) | Only `lo`, `hi` and `mid`. A recursive version uses O(log n) stack space. |

`lower_bound` always runs the full O(log n), since it never stops early.

## Gotchas

- **The input must be sorted.** On unsorted data, binary search gives wrong answers without any error.
- **Match the loop to the updates.** `while lo <= hi` goes with `hi = mid - 1`. `while lo < hi` goes with `hi = mid`. Mixing them causes an infinite loop or skips an item.
- **Duplicates.** The plain version returns any matching index. Use lower bound when you need the first one.
- **Overflow in other languages.** `(lo + hi) // 2` is safe in Python. In Java or C++, `lo + hi` can overflow. Write `lo + (hi - lo) / 2` there.

## In practice

Python's `bisect` module does this for you:

- `bisect.bisect_left(a, x)` is lower bound.
- `bisect.bisect_right(a, x)` returns the first index with a value `> x`.
- `bisect.insort(a, x)` inserts `x` and keeps `a` sorted. Finding the spot is O(log n), but inserting into a list is O(n).

`x in my_list` is a linear search. Sorting first costs O(n log n). So binary search pays off when you search the same data many times.

Binary search also works on questions, not only arrays. If a yes/no question flips from "no" to "yes" once as a number grows, binary search finds where it flips. Example: "What is the smallest speed that finishes the job in time?"
